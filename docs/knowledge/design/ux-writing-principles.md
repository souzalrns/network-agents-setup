# UX writing — princípios (knowledge pack)

## Voice (default lab)

| Princípio | Significado |
|-----------|-------------|
| Clear | Uma ideia por frase; palavras do utilizador |
| Concise | Cortar o dobro; depois cortar outra vez |
| Useful | Cada string ajuda a completar o job |
| Human | Tom de pessoa competente, não de manual de 1998 |
| Honest | Não prometer o que o sistema não faz |

## Mecânicas

1. **Sentence case** em títulos de UI e botões (excepto marcas/acrónimos).
2. **Botões = verbos** de acção concreta.
3. **Labels permanentes**; placeholder só como exemplo, não como único nome do campo.
4. **Não culpar** o utilizador nos erros.
5. **Não instruir só por cor ou posição** ("o botão vermelho").
6. **Voz activa** quando possível.
7. **Progressive disclosure** em onboarding: o mínimo para o próximo passo.

## Erros — what → why → how

```text
Não foi possível guardar o processo.     ← what
A ligação falhou.                        ← why (opcional)
Verifica a rede e tenta outra vez.       ← how
```

## Empty states

- Explicar o vazio em uma frase.
- Dar **uma** acção primária ("Criar processo").
- Evitar humor se o contexto for sério (jurídico, clínico, financeiro).

## Loading

- Preferir progresso específico ("A carregar processos…") a spinners mudos quando a espera é longa.

## Onboarding in-product

- Uma tarefa por passo.
- CTA alinhado ao job ("Continuar" só se o destino for óbvio; senão nomear o destino).

## Relação com marketing

| UX writing | Marketing copy |
|------------|----------------|
| Dentro do produto | Campanha, SEO, social |
| Reduz fricção | Persuade / posiciona |
| Estados de UI | Narrativa de marca |
