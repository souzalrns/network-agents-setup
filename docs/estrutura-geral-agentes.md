## 8. Orquestração Multi-Agentes
| Providência | Descrição |
|-------------|-----------|
| P-AG-108 | Adotar modelo **híbrido de orquestração**: Hierárquico + Router + Plan-and-Execute. |
| P-AG-109 | Orquestrador Geral (Camada 1) usa **Router** para decidir a área (domínio). |
| P-AG-110 | Cada Área de Domínio tem seu próprio **Orquestrador de Domínio**. |
| P-AG-111 | Dentro de cada domínio, usar **Plan-and-Execute** para tarefas complexas. |
| P-AG-112 | Agentes Transversais (Critic, Research, etc.) são chamados **sob demanda**. |
| P-AG-113 | **Não usar** orquestração descentralizada (peer-to-peer) em produção devido ao alto risco de comportamento caótico. |
| P-AG-114 | Para sistemas maduros, considerar **orquestração baseada em grafo (LangGraph)** com estados e transições explícitas. |

## 9. Recomendações Gerais de Implementação

| P-AG-115 | **Começar pequeno:** Orquestrador + 3–5 especialistas por área (ex: Suporte, Vendas, Financeiro, RAG e Validador). |
